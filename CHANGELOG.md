# Changelog

All notable changes to Coquille Revue. Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versions follow [Semantic Versioning](https://semver.org/). Entries are written in English from version 2.6.0 on.

## [2.6.0] — Unreleased

### Breaking changes

- **WP-CLI in English**, with no alias for the 2.5.0 names (WP-CLI refuses unknown options):
  - `apply` options: `--toutes` → `--all`, `--ignorer-alertes` → `--alerts-reviewed`, `--texte=<fichier>` → `--text-file=<file>`, `--champ=<champ>` → `--field=<field>`.
  - `locate` output: `present_sur_la_page` → `found_on_page`, `alertes` → `alerts`; in `occurrences`, `champ` → `field`, `nombre` → `count`, `forme` → `form`, `ligne` → `line`, `modifiable` → `writable`, type `fichier` → `file`, forms `exacte` → `exact`, `typographie simplifiée` → `straight_quotes`, `insécables en &nbsp;` → `nbsp_entity`.
  - `apply` report: `applique` → `applied`, `champ` → `field`, `forme` → `form`, `avant` → `before`, `apres` → `after`.
  - Help texts and messages are in English, and never translated.
- **JSON export** (admin button and `wp coquille-revue list`): `_avertissement` → `_warning`, `alertes` → `alerts`. Alerts are fixed codes: `web_address`, `code_or_command`, `invisible_characters`, `mixed_scripts`, `instruction_or_authority`, `long_addition`, `added_symbols`, `unreadable_text`, still followed by the code points involved (`invisible_characters (U+200B)`, `added_symbols (U+0022)`). The `source` values are codes: `logged_in_user`, `anonymous_unverified`.
- **Markdown export**: the instructions for Claude Code, the introduction and the data block are in English and never translated (`author:` instead of `auteur:`, area line `zone: x=… y=… width=… height=…`); each annotation heading shows its type, mode and source codes. Only the titles meant for people (title, date line, footer) are translated.
- **Rules for Claude Code** (exports): rewritten in English, never translated, so that a translation can never weaken them.
- **Claude Code plugin 2.6.0**: `/coquille-revue:apply-review` is in English (it answers in the user's language) and stops when the export comes from a WordPress plugin older than 2.6.0 (no `_meta.plugin_version` key, or no `alerts` key). Update the WordPress plugin and the Claude Code plugin together.
- **Stored values**: an anonymous visitor who gives no name is stored with an empty author name (it was `Anonyme`), shown as “Anonymous” in the language of the screen; existing rows keep `Anonyme`. The original text recorded for an area without text is `(zone without text)` (it was `(zone sans texte direct)`).
- **Public credit off by default**: the “plugin by Atelier 4F Digital” link is no longer shown in the visitors' review bar, and pages no longer carry an HTML comment with the plugin name and version. A per-site setting (off by default) shows the credit in the information popover of the pencil button; the credit stays on the admin page and in the exports and README files.
- **WordPress 6.2 minimum** (it was 5.8): every SQL query passes the table name through the `%i` placeholder of `$wpdb->prepare()`, introduced in that version.
- **Keyboard shortcut**: Ctrl+Shift+R (the browser's hard reload) is no longer taken over. Review mode is toggled with **Alt+Shift+C** (Option+Shift+C on Mac), for logged-in users only, and never while typing in a field.
- **REST API**: the `platform` field, ignored by the server, is no longer declared nor sent by the script (an older script that still sends it is accepted). Every field is validated (type, length, allowed values) before it is sanitized: a value of the wrong type (an array instead of a string, for example) gets a 400 error instead of crashing PHP; a field that is too long gets 400, no longer 413. The original text and the suggestion must be at least 2 characters long. `PATCH /annotation/{id}/status` requires the `status` parameter (it defaulted to `applied`). `GET /annotations` is paginated: `per_page` (at most 100, 100 by default) and `page`, with the totals in the `X-WP-Total` and `X-WP-TotalPages` headers. Its `created_at` and `applied_at` fields are in the site time zone, like the exports (they were the raw database value), and the new `created_at_gmt` and `applied_at_gmt` fields give them in UTC, like `date` and `date_gmt` in the WordPress API.
- **WP-CLI `apply --type=option`** only changes text options of the site: `blogname`, `blogdescription`, `widget_*`, `theme_mods_*`, `options_*` (ACF), a list that the `coquille_revue_cli_writable_options` filter can extend. `locate` tells for each option whether it is `writable`. `locate` and `apply` refuse an original text shorter than 2 characters.
- **Thank-you email**: a generic message, with none of the text typed by the visitor (no name, title or excerpt), with the date, the site name and a link to the home page. The sender is the WordPress one (`wp_mail_from` and `wp_mail_from_name` filters): no more `From` or `Reply-To` set to the administrator's address.
- **Injection test kit** renamed: `tests/injection/insert-cases.php`, `export-cases.php`, `delete-cases.php` and `cases.json` (keys `category`, `expected` and `language`).

### Added

- **Translation-ready interface**: every text shown to visitors and administrators, sent by email or returned by the REST API is an English source string of the `coquille-revue` text domain, loaded on `init` from the `languages/` folder (`Domain Path`). The folder ships the `coquille-revue.pot` template and a complete French translation (`.po`, `.mo` and `.l10n.php`). The script's texts are passed in `window.coquilleRevueConfig.i18n`.
- `_meta.plugin_version` key in the JSON export, read by the Claude Code plugin.
- 13 new prompt injection cases in `tests/injection/cases.json` (30 cases in all): 11 in English, and 2 (French and English) with an instruction hidden in invisible Unicode “Tag” characters. `insert-cases.php` also publishes a page that holds the original texts and points the annotations to it; `delete-cases.php` deletes it.
- Per-site “Thank-you email” setting (on by default) on the admin page, for the site's administrators only. When it is off, visitors are no longer asked for their email, the email is not stored, and the privacy texts are adapted. The `coquille_revue_notify_contributor` filter (`$enabled`, `$row`) decides annotation by annotation.
- Admin page: 50 annotations per page with pagination, alerts under each suggestion (the same alerts as in the exports for Claude Code), full original text and suggestion on hover, confirmation before “Applied” when a thank-you email is about to be sent.
- Per-site “Credit” setting (off by default), for the site's administrators only. Both site settings (thank-you email and credit) are saved by a single form.
- `coquille_revue_load_overlay` filter (boolean): return `false` to keep the review interface off a page.
- Uninstall: deleting the plugin from the Plugins screen removes the annotations table, the settings and the scheduled tasks, on every site of the network (`uninstall.php`). Deactivating keeps everything.
- `readme.txt` in English for the WordPress.org directory (description, privacy, FAQ, changelog).
- **Try it in WordPress Playground** link in the README files: `wporg-assets/blueprints/blueprint.json` installs the latest release, turns on public mode and opens a sample page to review.
- Releases also carry `coquille-revue.zip` (fixed name), so that `releases/latest/download/coquille-revue.zip` always points to the latest version.
- Development tools, left out of the zip (see `CONTRIBUTING.md`):
  - Composer development dependencies with exact versions and a lock that installs on PHP 7.4 to 8.4: PHP_CodeSniffer with WordPress Coding Standards 3 and PHPCompatibilityWP, PHPUnit 9.6 and the PHPUnit Polyfills.
  - `phpcs.xml.dist`: security, database and WordPress API rules, prefixes, text domain, WordPress 6.2 and PHP 7.4 minimum (0 errors, 0 warnings).
  - PHPUnit integration tests (`tests/phpunit/`) with the WordPress test suite: REST API, personal data, CSV, thank-you email, alerts, Markdown and JSON exports, WP-CLI commands (every refusal of `apply`, through a WP-CLI stand-in declared in the test bootstrap), admin actions and page, loading of the files, database upgrade, and site isolation on multisite. The `isolated` group (trusted proxy header, uninstall) runs in a pass of its own. `bin/install-wp-tests.sh` installs the test suite without svn; `bin/test-local.sh` runs the tests on Windows with the PHP and MySQL of Local, on a dedicated database (it refuses a `WP_TESTS_BASE` path with spaces, which the installer does not quote, and writes its `php.ini` at every run).
  - GitHub Actions (`.github/workflows/ci.yml`): PHP syntax from 7.4 to 8.4, PHPCS, JavaScript and shell syntax, PHPUnit (PHP 7.4 with WordPress 6.2, PHP 8.3 with WordPress 7.1, and multisite), Plugin Check on the contents of the zip; on a `v*` tag, a draft release with the zips once the tag, the header and the constant match.

### Changed

- The thank-you email and the digest email to the administrator are sent in the site language, whatever the language of the person whose action triggers them.
- Admin page: status, type and mode labels are translated (the stored values do not change), dates use a translatable format and numbers the number format of the language. Alerts are shown with translated labels.
- `wp coquille-revue locate` gives the status of each post where the text is found (a draft or a private post is not what visitors saw). When the text appears several times at one location, `apply --all --dry-run` shows an excerpt of each occurrence (`each_occurrence`), so that the user sees every place before replacing them all. `apply` no longer needs the PHP mbstring extension to build its report.
- Claude Code plugin: an annotation whose text is not on the annotated page (`found_on_page` false) is classified as “not found”, even when the text exists elsewhere; when the page cannot be read, the user is told and asked to confirm the location; drafts and private posts are flagged; zones are located too; a long export is read in several parts and its count checked against `_meta.count`.
- `wp coquille-revue locate` skips the plugin's own translation files in `wp-content/languages/plugins` (an annotation on a text of the Coquille Revue interface must not lead to editing a translation that the next update overwrites).
- The annotation bubble is fixed on the screen, just above the bar (or at the top when it would hide the selected text): it stayed attached to the first screen of the page, so after scrolling it went off screen and the page jumped when typing. In review mode, the pencil and the messages move above the bar, where they used to hide the “Stop” button.
- Touch screens: the bubble opens once the selection is stable (long press, then handles, which update it without erasing the remark) and without opening the keyboard; it sits above the virtual keyboard. The “click and drag over an area” hint is hidden, buttons are larger and fields use 16 px (iOS no longer zooms in when typing). The Enter key of the mobile keyboard shows “Send” and sends the remark, like the “Send” button.
- Accessibility of the public interface: SVG icons (no more emoji), typed and named buttons (“Close” on the cross, 32 px hit area), pencil and remark types announced as toggle buttons (`aria-pressed`), bubble with `role="dialog"` named by its title, labelled fields with the keyboard instructions outside the placeholder, confirmation or error message announced (`role="status"`), invalid email flagged (`aria-invalid` and a message). The information popover also opens on keyboard focus of the pencil; when the bubble or the bar closes, focus returns to the pencil. Visible focus everywhere, text contrast of at least 4.5:1, animations off when the system asks for reduced motion. Annotation works with the keyboard alone: in review mode, select the text (caret browsing, F7) then press Enter. The shortcut is shown in the information popover (`aria-keyshortcuts` on the pencil).
- Public interface: no longer loaded in the Customizer preview. Click-and-drag outside the open bubble sends the typed remark (or closes the bubble) instead of starting a new area that erased that remark; the cursor is recomputed each time review mode starts.
- Public interface: the CSS and JavaScript are no longer written into every page. WordPress loads them from `assets/css/overlay.css` and `assets/js/overlay.js` (script in the footer, `defer`), with the plugin version as `?ver=`. The configuration (API address, token, maximum lengths, texts) is passed in `window.coquilleRevueConfig`. Nothing is loaded when the interface is not shown (private mode and visitor not logged in). With a strict CSP, only this inline configuration needs a nonce (`wp_inline_script_attributes` filter); without it, the pencil button is not shown. After an update, purge the page cache; if an optimization tool delays or combines scripts, exclude `coquille-revue`.
- Admin page: styles in `assets/css/admin.css`, loaded only on the Coquille Revue page (no more `style` attributes). Darker status colors, for a contrast of at least 4.5:1; WordPress icons (dashicons) instead of emoji; every text is escaped when it is printed.
- Admin page: the confirmation before “Applied” uses a `data-coquille-confirm` attribute and a small script loaded by WordPress, instead of an `onclick` attribute. Status links of a page opened before the update no longer work (“The link you followed has expired”): reload the page.
- Plugin header in English, following the WordPress.org rules (short description, `Requires at least`, `Domain Path`).
- Alerts: the code points (U+XXXX) of invisible characters and mixed alphabets are computed without the PHP mbstring extension, which WordPress does not require.

### Fixed

- Dates: `created_at` and `applied_at` are stored in UTC, and shown in the site time zone on the admin page, in the exports, in the thank-you email and in the personal data export. `created_at` came from the clock of the MySQL server and `applied_at` from the site time zone, so an annotation could look applied before it was created, and every date was shifted when MySQL and WordPress use different time zones. Annotations created before 2.6.0 keep the time of the MySQL server (nothing changes when it runs in UTC, as on most hosts).
- Admin page: the page, original text and suggestion columns were a dozen pixels wide at 1,280 px. The alerts are now shown under the suggestion and the mode next to the type, instead of two columns of their own, the short columns are narrower, and when the screen is too narrow the table scrolls horizontally instead of squeezing these three columns.
- Admin page: after an action, its message (“Status updated.”, “Settings saved.”) no longer comes back on every change of page; a negative page number (`paged=-5`) shows the first page instead of the last one.
- Public interface: the pencil button is only shown once the script has run. Under a strict CSP without nonce, or when an optimization tool delays or breaks the script, visitors no longer see a button that does nothing.
- Public interface: the selected passage stays highlighted while the bubble is open (CSS Custom Highlight API, in recent browsers); the browser cleared the selection as soon as the field took the focus.
- Public interface: “Your text is too long” shows again. Since 2.6.0 validates every field, a too long field gets a 400 error, which the script did not recognize.
- Public interface: error messages are announced at once (`role="alert"`), and the information popover is a named region. Public pages no longer carry four HTML comments in French.
- French translation: the email signature no longer reads “L’équipe de Acme…” (missing elision before a vowel) but “L’équipe du site « Acme… »”, and the review bar reads “Sélectionnez du texte ou faites un cliquer-glisser sur une zone”.
- The label of the Credit setting quotes the credit as it is shown (“Coquille Revue plugin · by Atelier 4F Digital”), like the README files.
- Admin page and CSV export: an area without text shows “(area without text)” in the language of the screen instead of the stored marker. The stored value, `(zone without text)`, does not change and stays in the exports for Claude Code.

### Security

- Thank-you email: at most 1 email per address per day, and 20 per day per site; a double click or two simultaneous calls on “Applied” send a single email. It includes the sentence “If you did not make this suggestion, please ignore this message”.
- CSV export: a cell that starts with `=`, `+`, `-`, `@`, a tab or a line break is prefixed with an apostrophe, so that a spreadsheet does not run it as a formula; quotes are doubled, with no escape character.
- Markdown export: in the data block, every line of a value is indented by two spaces; a visitor can no longer write a fake `url:`, `author:` or `suggestion:` line. Translated titles are kept on a single line.
- Alerts: `web_address` also matches `mailto:`, `tel:`, `data:`, `//host` and domains without `www` with common extensions (`.ru`, `.co`, `.io`…); `apply` refuses to add such links. The instruction or authority wording is searched in French and in English together, whatever the site language, and these word lists are never translated.
- “Delete all” is a form (POST) with a required confirmation box: the confirmation works without JavaScript and under a strict CSP, and a mere link, even with a valid token, no longer deletes anything.
- Anti-spam: on top of the existing limits, at most 10 anonymous submissions per hour per IP address, so that a single address cannot use up the site's quota (30 per hour).
- Admin page: a crafted URL parameter (`coquille_revue_msg[]=1`, `format[]=…`) no longer crashes the page; links opened in a new tab have `rel="noopener noreferrer"`.
- Status change from the admin page: the security token is checked before any URL parameter is read.
- CSV, JSON and Markdown exports and `wp coquille-revue list` read the database in batches of 500 and write as they go: memory stays stable whatever the number of annotations.
- Alerts, wider detection:
  - `invisible_characters` covers every format character (Unicode category Cf: the “Tag” characters U+E0000–U+E007F that hide a text an AI can read, U+061C, U+180E, U+2061–U+2064…), private use characters, Hangul fillers, the braille blank and variation selectors (a single U+FE0E or U+FE0F after an emoji is not flagged, nor the Tag characters of a valid emoji flag such as the flag of England).
  - `mixed_scripts` also covers lookalike letters from the Armenian, Cherokee, Coptic, Lisu and Canadian syllabics alphabets, and full-width Latin letters in a text without Chinese, Japanese or Korean characters.
  - `code_or_command` and `web_address` also read a decoded copy of the text (`\uXXXX` sequences, HTML entities, numeric character references even without their semicolon as browsers read them, such as `&#106avascript:`, ASCII `%XX` sequences, full-width forms); `code_or_command` flags these encoded forms and `on…=` or `style=` attributes too. Only ASCII `%XX` sequences are decoded, so that a typo such as “20%de remise” is neither unreadable nor code.
  - `web_address` also matches known link shorteners (`t.me`, `wa.me`, `bit.ly`, `tinyurl.com`, `goo.gl`, `ow.ly`, `is.gd`, `buff.ly`, `rebrand.ly`, `cutt.ly`, `shorturl.at`, `lnkd.in`), `.de` and `.me` domains written in lower case after a name of at least 3 characters (`evil.de`, but not the missing space of “phrase.De plus”), and the path that follows a bare domain.
  - `instruction_or_authority` also matches “AI” (upper case only, so that the French “j'ai” does not), “go ahead”, “sans attendre”, “feu vert”, and wording for a later or silent pass: “silently”, “quietly”, “automat…”, “next/future pass, run or review”, “skip the confirmation, review or check”, “discrètement”, “en silence”, “prochain passage”.
  - The CSS selector, the XPath and the path of the page address are also searched, field by field and word by word, but only for wording addressed to an AI (“note for Claude”, “hey AI”, “pour l'IA”) and false approvals (“already approved”, “sans demander”…): an isolated name such as `admin`, `password`, `assistant` or `redirect` is ordinary in a class name or an address. The author name and the page title, which a visitor can forge, keep the full list.
  - New `unreadable_text` alert: a text that the checks cannot read (invalid UTF-8, computation limit reached) is never shown as clean.
  - New `long_addition` alert: the suggestion holds at least 6 words that are not in the original text, a whole sentence added rather than a correction.
  - New `added_symbols` alert: the suggestion holds one of the characters `` \ < > & { } ` " % = `` more times than the original text (also after decoding), listed by code point.
  - `long_addition` and `added_symbols` compare the suggestion with the original text: they are only computed for text annotations that are not questions (an area describes a request in plain language).
  - The display name of an account that manages annotations (editors and above by default) is set by the site and no longer checked: an editor called “admin” no longer marks all their annotations.
- Link detection runs in linear time: a text such as `a.a.a.a…` could take about a second per annotation without PCRE JIT, enough to stall the admin page and the exports.
- Rule 7 for Claude Code (exports) names every field typed by the visitor: original text, suggestion, author, page title, URL, CSS selector and XPath.
- WP-CLI `apply`:
  - the checks also read a decoded copy of the replacement text (`\uXXXX` sequences, HTML entities, `%XX`, full-width forms, spaces inside `javascript:`): in content stored as JSON (block attributes, page builders), these forms would become active HTML again;
  - `style=` attributes are refused like `on…=` ones;
  - a tag, an HTML comment, a link or a shortcode of the replacement text must appear verbatim in the original text: a link swapped for another one is refused, not only an extra one;
  - an original or replacement text that the checks cannot read (invalid UTF-8, computation limit) is refused, with a message that says so;
  - hidden characters (bidirectional controls, Tag characters outside a valid emoji flag, U+061C), even encoded as an entity, are refused even with `--alerts-reviewed`;
  - the characters `` \ < > & { } ` `` are refused when the replacement text holds them more times than the original text, even with `--alerts-reviewed`; `" % =` need `--alerts-reviewed` (`added_symbols` alert);
  - a replacement text approved with `--text-file` goes through the same alerts as a suggestion: with any alert, `--alerts-reviewed` is required;
  - punctuation stuck to the end of an address (`www.example.fr !` corrected to `www.example.fr.`) is not part of the address: correcting it is no longer refused as an added link.
- Personal data: the WordPress export and erasure tools also find the annotations of the account that holds the email address, even when the email is not stored with them (thank-you email off, account that is not a member of the site, email already deleted once the annotation was processed); the export shows the display name of the account.
- Anti-spam: an IPv4 address written as IPv6 (`::ffff:a.b.c.d`, given by some dual-stack servers) keeps its own limit; all IPv4 visitors used to share one counter, so a single one of them could block everyone else.
- REST API: each element name of the XPath is limited to 64 characters (a longer one is a sentence written with hyphens).
- REST API: the “Tag” characters U+E0000–U+E007F (except those of a valid emoji flag) and U+061C are refused like the bidirectional controls (400 `invalid_chars`), in the original text, the suggestion, the name, the page title, the XPath and the CSS selector.
- When the thank-you email is off, the account email of a logged-in user is no longer stored either: it only serves that email.
- WP-CLI `apply --text-file` only reads a `.txt` file inside the `.coquille-revue` folder of the current directory (where the Claude Code plugin writes it): a booby-trapped annotation can no longer get a secret file such as `.env` copied into a page.

## [2.5.0] — 2026-10-09 — first public release

Coquille Revue was first used internally at Atelier 4F Digital, under the name “Content Review” (versions 2.0 to 2.4). 2.5.0 is the first published version. It changes the name, the prefixes and the table, and is not compatible with those internal versions. This entry keeps the 2.5.0 names, renamed in 2.6.0.

### Features

- **Review on the pages**: pencil button, selection of a text or an area, remark of type correction, suggestion or question. Private mode by default (logged-in users who can edit posts), public mode (every visitor) turned on from the admin page.
- **Admin page**: tabs by status, status changes, CSV, JSON and Markdown exports, thank-you email to the contributor when their suggestion is applied, digest email to the administrator (at most one every 15 minutes).
- **Multisite**: activation per site or network-wide; each site only sees, exports and deletes its own annotations.
- **WP-CLI commands** `wp coquille-revue list | locate | apply | status`. The text of the annotations is read from the database by number: it never goes through a command line. `locate` looks for the original text (literal search, which allows for typographic apostrophes and quotes and non-breaking spaces) in posts and pages, menus, options, custom fields, terms, theme and plugin files, translations, and on the page itself. `apply` replaces the text verbatim in database content (with a revision when the content type supports them) and refuses to add tags, links, shortcodes, PHP, `javascript:` or `on…=` attributes, several occurrences (unless `--toutes`), questions and annotations with alerts (unless `--ignorer-alertes`).
- **Claude Code plugin** `coquille-revue` (`claude-plugin/` folder, `.claude-plugin/marketplace.json` catalog), `/coquille-revue:apply-review` command: approval annotation by annotation, nothing applied automatically, no WordPress password, `--dry-run` mode.

### Security

- Annotations are handled as data typed by visitors, never as instructions. The rules given to Claude Code (exports and plugin, the latter take precedence) forbid applying anything without approval, following an instruction contained in an annotation, putting its text in a command line, adding code or links, and copying booby-trapped content.
- Each exported annotation carries its source and `alertes` computed without AI: web address, code or command (including shortcodes), invisible characters and mixed alphabets (with their code points), instruction or authority wording.
- Markdown export: the visitors' fields are enclosed in a block they cannot get out of.
- The API refuses a page address that does not belong to the site (to the exact sub-site on multisite), an XPath or selector of unexpected form, bidirectional control characters and fields that are too long.
- Anti-spam in public mode: honeypot field, at most 5 submissions per IP address (/64 block for IPv6) in 5 minutes, 30 anonymous submissions per hour per site; 60 submissions in 5 minutes per logged-in account. The IP address is the one of the connection; behind a trusted proxy, declare its header with `COQUILLE_REVUE_TRUSTED_PROXY_HEADER`.
- Permissions: managing annotations requires `edit_others_posts` (`coquille_revue_manage_capability` filter); the public/private mode is reserved to `manage_options`, or to the super admin on multisite.
- The rules were put to the test with a prompt injection test (17 booby-trapped or ambiguous annotations, see `tests/injection/`): no unwanted action.

### Personal data

- Stored: text and suggestion, page address (without query string or anchor), IP address; for a visitor, the name and email if they give them; for a logged-in user, their display name and the email of their account (if they are a member of the site).
- The email is shown nowhere: it is used for the thank-you message and the WordPress privacy tools. The IP address is visible to administrators (admin page, CSV export). Neither the email nor the IP address is sent to Claude Code (API, JSON and Markdown exports, WP-CLI).
- Retention: the IP address is erased after 30 days; a visitor's email and name within 24 hours after the annotation is processed (applied, rejected or archived), and after 6 months at the latest. The annotations of a deleted site are erased.
- Notice under the form, suggested privacy policy text, support for the WordPress personal data export and erasure requests.
